Running the full ingestion pipeline — and knowing it actually worked

Ingestion is the batch job that turns your raw files into searchable vectors. This is how to run it over everything at once, and how to read the output to confirm it did what you think.

First: what "ingestion" even is

Two separate programs live in this repo. It helps to keep them straight.

Ingest (build time)

A one-shot batch script. Reads your source files, cuts them into chunks, turns each chunk into a vector, and writes them to the vector store. You run it by hand, occasionally.

Chatbot (query time)

The Streamlit app. Never touches your raw files — it only searches the vectors ingestion already wrote. If a fact isn't ingested, the bot can't answer from it.

"Run full ingestion end-to-end" means: execute that build-time script over all source types in one pass — PDFs, markdown, plain text, cached web articles, and YouTube transcripts — rather than debugging one loader at a time. It's the last check before the knowledge base is considered real.

The pipeline, end to end

Everything below happens inside a single command: uv run python -m src.ingest. The run() function in src/ingest.py orchestrates it.

Step 1 URLs → markdown cache web_loader.py
Step 2 Load every source type loaders/*.py
Step 3a Split into chunks RecursiveCharacterTextSplitter
Step 3b Embed + store vectorstore.py

Walking through a full run

Each step with the real code from src/ingest.py and what to look for in the printed output.

Make sure real content is actually in place

This is the "once real content is in place" precondition on the card. Ingestion can only index files that exist. Before running, confirm each source folder has what you expect — empty folders silently contribute zero documents.

# the folders ingestion reads (from src/config.py)
data/raw/pdf/        # PDFs (OCR fallback for scanned pages)
data/raw/markdown/   # hand-written .md notes
data/raw/text/       # plain .txt
data/raw/web_cache/  # auto-filled from data/urls.txt in step 1
data/urls.txt        # article URLs to fetch
data/youtube_urls.txt # video URLs to transcribe

Run the one command

From the project root. uv run uses the project's .venv (Python 3.14) so you don't have to activate anything. The -m flag runs it as a module so the src package imports resolve.

uv run python -m src.ingest

Step 1 fires: URLs become cached markdownweb_loader.py

ingest_urls_from_file() reads data/urls.txt, fetches each page, strips nav/ads/boilerplate with trafilatura, and writes clean markdown into data/raw/web_cache/. That's why web articles get loaded in step 2 alongside your hand-written markdown — by then they're just files on disk.

=== Step 1: Converting URLs to markdown ===

Step 2 fires: every loader runs and tags its docs

Each loader returns LangChain Documents carrying a source_type tag (pdf, markdown, text, youtube). They're concatenated into one list. The merged count is your first real signal — if it's suspiciously low, a folder was empty or a loader failed.

all_docs = pdf_docs + markdown_docs + text_docs + youtube_docs
=== Step 3: Merged total documents: 214 ===

Step 3a: documents are split into chunks

RecursiveCharacterTextSplitter cuts each document into ~1000-character pieces (CHUNK_SIZE) with 150 chars of overlap (CHUNK_OVERLAP) so a sentence spanning a boundary isn't lost. Chunk count is always ≥ document count — a long PDF becomes many chunks. This is the number the card asks you to "confirm."

[ingest] Split 214 documents into 1,883 chunks

Step 3b: chunks are embedded and written to the vector storevectorstore.py

Each chunk is turned into a 384-dim vector by all-MiniLM-L6-v2, then written to whichever backend VECTORSTORE_BACKEND names — Pinecone's pm-course index by default, or a local Chroma store. This final line is your "vector store writes look right" confirmation.

vs = get_vectorstore()
vs.add_documents(chunks)
[ingest] Stored 1,883 chunks in pinecone vector store
[SUCCESS] Ingestion complete.

Confirming it "looks right" — per source type

The card asks you to confirm counts for every source type. The default output only prints totals, so here's how to actually verify each one carried through.

Cross-check each loader in isolation
  • Run each loader standalone — every one has a __main__ block that prints what it loaded: uv run python -m src.loaders.pdf_loader, then markdown_loader, text_loader, youtube_loader. If PDF prints 40 docs and text prints 0, you know text is empty before a full rebuild.
  • Watch the merged total in step 2. Add up the standalone counts — they should equal the merged number.
  • Query the store after: launch uv run streamlit run app.py and ask a question you know is answered by a PDF, then one answered by a YouTube video. The bot returns source chunks, so you can see each source_type come back.
The one gotcha that will bite you
  • Ingestion appends — it does not replace. store_chunks() calls vs.add_documents(chunks) with no delete first. Run it twice and you get two copies of every chunk in the index. Counts will look "wrong" (doubled) and retrieval quality drops from duplicate hits.
  • So a true "end-to-end rebuild" means clearing first. For Chroma, delete vectorstore/chroma_db/. For Pinecone, delete the vectors in the pm-course index (or recreate it) before re-ingesting. Then the printed chunk count should match the index's vector count.
  • Verify the final count matches. After a clean run, the Pinecone dashboard (or Chroma's collection.count()) should equal the "Stored N chunks" line. If they differ, something was written twice or a write failed.

When to run it

Ingestion is not something you run on every code change — only when the content or the indexing recipe changes.

  • ✓You added, removed, or edited files in any data/raw/* folder.
  • ✓You added URLs to data/urls.txt or videos to data/youtube_urls.txt.
  • ✓You changed CHUNK_SIZE, CHUNK_OVERLAP, or the embedding model — the vectors must be rebuilt to match.
  • ✓You switched VECTORSTORE_BACKEND or pointed at a fresh/empty index.
  • ✕You only edited chatbot.py, app.py, or the prompt — that's query-time code, no re-ingest needed.
  • ✕You're just restarting the chat UI. The vectors persist; ingestion already did its job.
