How a YouTube video becomes something the chatbot can answer from

One URL in a text file turns into a searchable chunk of knowledge. Here's the exact path it travels through this repo, file by file.

The pipeline, end to end

Five hops from a pasted link to a vector the chatbot can retrieve. Everything here happens inside uv run python -m src.ingest.

Input URL list data/youtube_urls.txt
Extract ID Regex on the URL youtube_loader.py
Fetch Caption transcript youtube_transcript_api
Wrap LangChain Document source_type: "youtube"
Store Chunk → embed → save vectorstore.py

Walking through it

The same five hops, expanded with the actual code that runs at each one.

Drop the link in a text filedata/youtube_urls.txt

One URL per line. Lines starting with # are treated as comments and skipped. This file is the only thing you edit by hand — no code changes needed to add a video.

# data/youtube_urls.txt
https://youtu.be/GNdIb-h5BPg?si=ZUcnHHlDbbD0-epf

Run ingestion

This kicks off the whole batch pipeline — PDFs, markdown, web cache, and YouTube all get reloaded and rewritten to the vector store in one pass.

uv run python -m src.ingest

The loader pulls the video ID out of the URLyoutube_loader.py

A single regex handles both link shapes YouTube hands out — the short youtu.be/… form and the long watch?v=… form — and grabs the 11-character ID either way.

re.search(r"(?:v=|youtu\.be/)([a-zA-Z0-9_-]{11})", url)

The transcript is fetched and joined into one block of text

youtube_transcript_api returns the video's caption track as timed snippets. The loader throws away the timestamps and joins the text with spaces — so this is good for "what does the video say," not "what's said at 3:42."

fetched = ytt_api.fetch(video_id)
full_text = " ".join(s.text for s in fetched)

It's wrapped as a tagged Document, then chunked and embedded like everything else

The source_type: "youtube" tag is what lets the chatbot cite where an answer came from later. From here it's indistinguishable from a PDF or markdown page — same splitter, same all-MiniLM-L6-v2 embeddings, same Pinecone/Chroma store.

Document(
  page_content=full_text,
  metadata={"source": url, "source_type": "youtube"}
)
Worth knowing before you add videos
  • Public videos only. The loader's own docstring warns it off paywalled course platforms — it needs an openly available caption track.
  • No transcript = silent skip. If captions are off, or the video is private or age-restricted, fetch() raises, the loader prints an error, and that one video is dropped — the rest of ingestion still runs.
  • Timestamps don't survive. The whole transcript becomes one flat string before chunking, so retrieval can point you to a video but not a moment in it.
  • Not exported from the package. youtube_loader is imported directly by ingest.py rather than through src/loaders/__init__.py — intentional, matches how the other loaders are wired in.

Commands you'll actually use

uv run python -m src.ingest Rebuild the whole knowledge base — run this after editing the URL file.
uv run python -m src.loaders.youtube_loader Run just the YouTube loader standalone and print what it fetched — for debugging one video without a full rebuild.
uv run streamlit run app.py Launch the chat UI to ask questions against whatever's currently indexed.
